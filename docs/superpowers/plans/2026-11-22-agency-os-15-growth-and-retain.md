# Agency OS Plan 15: Grow and retain (client grade, capacity, batch board, post-launch ladder, auto-approve, Studio) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close Phase 3. Every client carries an A/B/C grade you set with a rule-based suggestion; Today and Money say how full your week and your client list are; one board shows a recurring step across all clients; a finished build starts a post-launch ladder of dated drafts; two kinds of fixed reminder can go out without you; and Studio turns real work into social images you approve and post by hand.

**Architecture:** Mostly reads and small writes over what Plans 7, 8, 11 and 13 already hold. Grade and capacity are pure functions plus one bulk reader each. The batch board is a grouped read of recurring `tasks`. The ladder is its own small table filled by an `onProjectDone` hook and drained by a daily sweep part that creates `ladder.mail` approvals. Auto-approve is one function called right after two existing approval creators; it runs the normal `approve()` path, so every send keeps its existing guards. Studio renders HTML to PNG with the Browser Rendering binding already used for PDFs and writes copy through a new Claude queue kind; it never posts anywhere.

**Tech Stack:** Cloudflare Workers + Hono, D1 (migration 0065), R2 (`RAW`), Browser Rendering (`BROWSER`), zod, React 19 SPA, vitest (Workers pool). No new service, no helper change, no dependency.

**Spec:** `docs/superpowers/specs/2026-11-17-agency-os-design.md` (copy at `~/Project Sites/agency/docs/specs/2026-11-17-agency-os-design.md`) §9.6 (batch views, capacity), §9.11 (Studio), §9.12 (ladder, grade, health), §9.13 (approval inbox, "Later, Logan can turn on auto-approve rules per type (e.g. 'invoice reminders on schedule')"), §9.14 (capacity vs 40-50 clients), §12 Phase 3.

## Scope

Plan 15 of the five Phase 3 plans (see Plan 11). In: grade, capacity, the batch board, the ladder, auto-approve for fixed reminders only, Studio (three post kinds), the kickoff deck, owner pages, two new MCP tools (`list_batches`, `get_studio_posts`) and grade and ladder shown in the existing client read. ## Global Constraints

- "Outbound actions only ever create Approvals." (§9.13) The only exception is Task 7: an approval of a fixed kind, created after its rule was switched on, is approved by `approve()` itself (never by a second send path). Nothing else in this plan sends mail, charges, publishes or posts.
- "Claude costs $0 extra" (§9.13): Claude work is a queue task (`registerTaskKind`), never an Anthropic API call. The grade suggestion and the capacity numbers are plain code, not a Claude call.
- Studio and ladder text shown to a client or posted for you never contains: invented results, testimonials, awards, prices, statistics or years in business; a ranking or result promise ("guaranteed", "#1", "first page"); a link, email address or markdown in Claude's words. Result schemas refuse the checkable ones.
- Private client data stays out of Studio: with `anonymize` on (the default) no business name, domain, address, phone, person name or city reaches Claude, a template or an image.
- Weeks start Monday, months and dates use the booking zone (`zoneOf`, `calendarDateIn`, `periodKey`), never UTC. Test clients and test projects are never counted, drafted or graded; a client with a billing hold gets no ladder mail and no auto-approval.
- Running cost stays at or under `$150/month`: this plan adds no paid call (Browser Rendering is already on the plan).
- Next migration is `0065_growth`. Remote has 0001-0064 applied (2026-11-22) and the Worker is deployed at version `e1d7ccd1`. Apply 0065 remotely BEFORE deploying (record a Time Travel bookmark first). Branch to cut: `feat/agency-os-growth` from `main` (e2c189a) in the worktree `~/Project Sites/site-search-agency-os` (currently detached at main). Subagents run on Sonnet.
- Verification: `npx vitest run <file>`, `npm test`, `npm run typecheck`, `npm run build`. Known flakes (`billing-flow`, `billing-sweep`, `projects-flow`, `sites-onboarding-items`, the MCP rate-limit test) pass alone.
